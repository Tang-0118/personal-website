01 已商用上线

无人车间人形安全防护系统 实时

多路工业相机 + YOLOv8 人员检测，检测到人就锁停设备——安全系统只允许「宁可误锁，不可误开」

面向无人车间的安全防护系统：机械臂等自动化设备运行时，一旦检测到人员进入设备区域，系统立即输出锁机信号停止设备，避免人员伤害。 我在项目中负责 YOLOv8 人员检测模型的训练与调优、检测与跟踪算法、多路相机的实时推理调度、安全状态机与上位机软件开发，并完成 CPU（2 路）/ GPU（4 路）两套现场版本的交付上线。

  • 检测与实时调度：YOLOv8 单类人员检测（conf 0.3 / NMS 0.5），2–4 路 1280×720 工业相机并发；推理按「只保留最新帧 + 轮询公平调度 + batch=1」组织，不等待凑批，避免高帧率相机饿死其它路与旧帧堆积
  • 多后端部署：以 ModelFactory 统一 backend 与模型协议，同一套业务链可在 PyTorch（CUDA / CPU）、ONNXRuntime CPU、算能 Sophon NPU（bmodel）之间切换，现场按算力选版本
  • 区域与方向判定：多边形 ROI 划分 ON / IN / OUT 三区，门区短轨迹状态机按位移投影（可叠加拓扑得分）判定 ENTER / LEAVE，对检测抖动与丢帧容错，输出设备内实时人数与进出净流量
  • Fail-Safe 安全链路：STARTUP_LOCK / PERSON_LOCK / FAULT_LOCK / UNLOCK 状态机——启动默认锁机、检测到人保持锁机、相机 / 推理 / 跟踪 / 计数 / IO 任一模块心跳超时即判故障并强制锁机；复位需同时满足「无人 + 无故障 + 模块健康」并在执行前二次复查
  • 时延验收与工控联锁：端到端以 T0 相机取帧 → T1 继电器写入成功为口径、限值 200 ms，拆成 acquire / scheduler / infer / rule / safety / io 六段统计 p95 / p99 与合格率；锁机经 Modbus RTU 继电器输出并保留 DI 软复位，IO 侧 3 次重试 + 死信队列 + 紧急锁机回调

02 已商用上线 计算机设计大赛 · 中南赛区三等奖

包装袋封口质量在线检测系统 BAGCheck 实时

红外热成像 + 可见光双相机，在线判定封口是否合格并驱动 PLC 剔除

面向产线的实时质检系统：每个包装袋经过工位时，红外与可见光相机同步各拍一张图，两路算法各自分析后按时间戳配对融合， 输出 OK / NG / UNKNOWN，NG 直接由 PLC 控制剔除机构踢出产线。我在项目中负责视觉算法与上位机软件的开发与调优。

  • 双相机同步：硬件触发 + 时间戳配对聚合，任一路异常即判 UNKNOWN，避免漏检
  • IR 侧量化：温度、宽度、高度、面积、倾斜、局部形变与异物；异物用「局部温度参考 + MAD 自适应阈值」，比固定阈值更适应不同袋型
  • RGB 侧：动态规划跟踪封口上边缘基准线 + RANSAC 拟合，抑制褶皱、银边、金属高光造成的假阳性
  • 配置驱动 + 规则引擎：阈值热更新，现场调参不用改代码、不用重新打包
  • 数据回溯：NG 图像回看页支持按 OK / NG / UNKNOWN + 日期时间筛选，提供「缺陷浏览 / 异常统计」双视图，逐条回看红外与可见光原图、缺陷框位置与判定原因，可翻页与导出
  • 日志记录：实时输出每条结果的 时间 / IR 状态 / RGB 状态 / 综合判定 / 原因，并实时统计 OK·NG·UNKNOWN 数量与合格率；日志文件与统计按天滚动留存、保留天数可配置
  • 证据链：原图、温度矩阵、标注图、结果 JSON 全留存，配独立离线回放工具批量重跑导出
  • 落地：Python 3.10 + PyQt5 + OpenCV，PyInstaller 打包交付，PLC 走 Modbus RTU 并带预检与 fail-safe

03 已通过真机验收

烟标质检助手 · HarmonyOS App 端侧

把 PC 上的烟标缺陷检测算法，搬进手机端跑

烟标（烟盒印刷品）表面缺陷的传统检测依赖固定机位与工控机。这个项目把整套算法迁移到鸿蒙手机上： 现场人员拍一张烟标照片即可出判定结果，适合产线抽检与巡线场景。 我在项目中负责鸿蒙端前端开发（ArkTS + ArkUI，样本库、拍摄检测、结果判定与历史管理）与视觉算法开发（缺陷检测流水线、配准与量测）。

  • 6 类检测能力：五行大字、固定文字行、侧边小字（焦油量/烟碱量等）、小图标、Logo 烫金套印、逐字浅印
  • 算法移植链路：PC 端测试集验证（17 张图真值）→ NAPI 链路 → C++ 移植 → 真机验收，逐值比对
  • 真机性能：单张 11–75 s（难图 75 s）；真机自动化验收 6/6 通过，与 PC 结果在容差内一致

04 华南赛区一等奖

xmesh · 并行三维谱元网格生成器 并行加速

面向地震动力学模拟的网格生成，跑在国家超算天河与曙光上

xmesh 为地震波传播求解器 SPECFEM3D 生成六面体谱元网格，在原生 xmeshfem3D 基础上做 MPI 并行与 Kokkos 异构加速，并用确定性的 SFC-3D 分区（Z 加权切分 + Hilbert 曲线排序）替代 SCOTCH。 我负责性能剖析与优化、海光 DCU 移植，以及天河与曙光两套超算上的全部实验：在天河上跑实验、收数据、出图， 并据此修改 xmesh 源码。

  • 天河 CPU 实验：在国家超算长沙中心天河集群 ft_module 分区（aarch64、64 核/节点）完成 8/16/32/64 进程强扩展与端到端实验，网格与分区阶段稳定在 3–5 s，负载不平衡 0.000%，64 进程端到端 754 s 跑通全流程
  • 曙光整体加速：单进程原始总耗时 1645.8 s → 8 进程修复后约 1.7 s，整体加速约 970×；32 进程降至约 0.8 s
  • 消瓶颈一：定位到 detect_mpi_interfaces 里的冗余集合通信，改为各 rank 本地确定性计算 → 8 进程 136.1 s → 0.24 s（569×）
  • 消瓶颈二：预计算界面双线性插值辅助量，把 O(nxi·neta) 热路径降为 O(1) → generate_mesh 274.0 s → 0.20 s（1362×）
  • 异构加速：海光 DCU（HIP + DTK）上，8 卡相对 128 核 CPU 的网格生成流水线加速 3.7–4.5×，雅可比行列式检查最高 12×
  • 多卡扩展：64 DCU 弱扩展总 wall 4.95 s，数据库写出聚合带宽 2161 MB/s；test 覆盖 25/25 通过
  • 真实地形验证：洛杉矶—北岭真实地形模型（19.6 万谱元）xmesh 网格雅可比全正、通过 xgenerate_databases；原生 SPECFEM3D + SCOTCH 流程在同一模型上产生反转单元并失败
  • 成果：2026 第十三届 PAC 并行应用挑战赛华南赛区一等奖；论文 PD-CAT 2026 在审
